# Brand assets

**This directory is not style rules.** Everything else in this package is a
convention you are meant to apply, adapt and argue with. What is here is
LUMIVATE's property: marks that identify the company, which have one correct
form and no adaptable one.

    lumivate/globe-cover.svg       the cover globe, light edition
    lumivate/globe-cover.dark.svg  the cover globe, dark edition
    lumivate/globe-mark.svg        the small mark, 64px and up
    lumivate/globe-mark-small.svg  the small mark, 16-48px

The cover pair is **two files, not one that adapts.** `prefers-color-scheme`
follows the browser rather than the page a mark is dropped on, so a mark that
adapts goes dark on a light deck read in a dark-mode browser. A document that
ships light and dark editions picks the file that matches its edition.

Both are generated by `scripts/build/build_brand.py` from the same projection and the
same topology as the figures, so the mark on a cover and the figure inside it
are the same object at two sizes.

## Using them

They are **self-contained**. Each carries its own styles inline, in one ink at
three strengths, so a mark dropped into a page that has never heard of
`tokens/` still renders — and so it survives being printed in one colour, which
is what a logo has to do. Do not restyle them from outside; a mark that changes
colour with its host is not a mark.

Pick by size, not by preference. The small one drops the graticule because
below about 48px a 15-degree grid falls closer together than the pixels; the
large one keeps it because above that it is what makes a disc read as a sphere.

## The live globe

The cover globe rotates when a document wants it to. Two commands, both of
which ship here, and nothing else:

    python3 scripts/render/globe_svg.py --preset cover     # the frame
    python3 scripts/build/embed_globe.py                  # the runtime, inline

Put the frame inside an element carrying `data-globe`, put the runtime once at
the end of the body, and it turns. `--preset cover` is the same view the static
pair is drawn from, so the still and the moving version are the same globe.

For a document that will be exported, add `data-globe-print-lon0="103.8"` to
the figure. `export_pdf.py` pins every globe on the page before it captures —
view **and** signal positions — so the same document exports the same frame
twice. Without it a PDF is a screenshot of whatever moment the browser reached.

This is what makes the globe reachable from any agent with the skill installed:
no demo machinery, no build directory, two commands that are already here.

## Changing them

`LOCKED.json` holds a SHA-256 for every file here and for the component that
produces them. `check_repo.py` fails, and CI blocks the merge, when one changes
without the same commit recording the new hash and a reason.

That friction is the point. It does not prevent an edit — nothing in a git
repository can — it prevents an edit from **merging unnoticed**, which is the
only thing a lock in source control can honestly promise.

To change a locked file: make the change, run `python3 scripts/lib/lock.py --update
"<why>"`, and put both in one commit. The reason goes in the file and stays
there, so the next person can read what was decided rather than guess.
